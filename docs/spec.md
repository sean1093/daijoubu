# 隨身旅伴 TravelBuddy（舊名：日本旅遊小幫手 Daijoubu）— 產品規格（v0.2）

> 給不會日文的台灣旅客，去日本時帶在手機裡的小幫手。
> 不用學日文、也不用開口：App 替你**念出來**，或把日文**放大給對方看**，10 秒內把事情辦完。
>
> 這是給所有人用的服務：UI 與文件都不使用針對特定年齡層或族群的稱呼。大字、大按鈕、不打字，是為了讓任何人在慌亂時都能用。

狀態：已確認，實作中。決定紀錄見 §11。

---

## 1. 使用者與核心流程

| 角色 | 什麼時候用 | 做什麼 |
|---|---|---|
| **設定者**（旅客本人，或幫忙的家人朋友） | 出發前，在自己的手機或電腦 | 填資料後直接使用；或產生連結／QR code 傳給旅客 |
| **旅客（使用者）** | 在日本，遇到狀況時 | 打開 → 點一個大按鈕 → 把手機拿給對方看或按播放 |
| **日本人（對方）** | 被旅客拿手機問的時候 | 看日文卡片；在「給對方點選」模式下用手指點答案 |

```
設定者：#/setup 填資料 ──► #/share 產生連結＋QR ──(LINE/當面)──► 旅客手機開啟 #/s/<資料>
                                                                │
                                                     匯入 localStorage，網址改回 #/
                                                                ▼
旅客：首頁 ──► 「我需要幫忙」／情境大按鈕 ──► 一句話 ──► 播放 or 給對方看 or 給對方點選
```

設計底線：

- **使用端零設定**：沒有登入、沒有選單樹、沒有輸入框、沒有搜尋。字體大小與深色模式放在首頁最下方的小連結。
- **沒有填資料也能用**：所有情境句都能用；需要站名或飯店的句子改用「這裡」「這間飯店」並提示「把地址拿給對方看」。
- **只有設定頁要打字**：表單只出現在 `#/setup`（首頁底部「設定資料」小字連結），使用中的畫面完全不需要輸入。

## 2. 功能（MVP，依優先順序）

### 2.1 預先設定 + 分享（`#/setup`、`#/share`、`#/s/…`）

**表單欄位**（全部選填，只有「稱呼」建議必填）：

| 區塊 | 欄位 | 備註 |
|---|---|---|
| 旅客 | 稱呼（中文，例：媽媽、小美） | 首頁顯示「媽媽，有需要就按下面的按鈕」；沒填就省略稱呼 |
| | 護照英文姓名 | 求救卡、醫療卡上給警察／醫院看 |
| | 出生年 | 醫療卡（醫院一定會問年齡）。只存年份。 |
| 飯店（可多筆） | 日文名稱、讀音（假名，選填）、地址（日文）、電話、入住日～退房日 | 依今天日期自動選「目前的飯店」；不在日期內就用第一筆 |
| 每天的行程（可多筆） | 日期（選填）、類型（車站／地點）、日文名稱、讀音（假名，選填）、中文名稱 | 例：車站「新宿」「しんじゅく」「新宿」。讀音讓語音不唸錯、也看得到拼音 |
| 家人聯絡 | 關係（女兒…）、姓名、電話（台灣手機）、LINE ID（選填） | 可多筆；第一筆是主要聯絡人 |
| 日本當地聯絡人（選填） | 姓名、日本電話 | 朋友、導遊、親戚。日本人最容易幫忙打的電話 |
| 健康 | 慢性病（勾選常見項目＋其他自填）、常用藥（**成分名**＋劑量）、血型（選填） | 自填欄位提示「請寫英文，日本醫師看得懂」 |
| 過敏與飲食 | 藥物過敏、食物過敏（勾選日本「特定原材料」等常見項目＋其他）、飲食限制（素食、不吃牛…） | 勾選項目都有預先寫好的日文 |
| 保險（選填） | 保險公司、保單號碼、24 小時救援電話 | 「我有旅遊保險」卡片會帶入 |

**分享**：

- 資料編碼在網址 `#` 後面（`#/s/1.<payload>`），**不送到任何伺服器**（`#` 之後的內容瀏覽器不會傳給伺服器；整個網站也沒有後端）。
- 畫面同時顯示：連結（「複製連結」按鈕，支援 `navigator.share` 時改為「分享」）、QR code、「列印護貝小卡」。
- 醒目提醒（固定在分享按鈕上方，不能收合）：
  > ⚠️ 這個連結裡有飯店地址、電話和健康資料。只傳給本人，不要貼到群組或社群。任何拿到連結的人都看得到這些資料。
- 設定者的裝置：資料存在本機，可以回來改、重新產生連結。旅客自己填的話，填完就直接能用，不必分享。

**旅客打開連結**（`#/s/1.<payload>`）：

1. 解碼、驗證。失敗 → 「這個連結好像不完整，請重新傳一次」。
2. 若本機已有資料且不同 → 「要換成新的資料嗎？」兩個大按鈕（換新的／保留原本的）。相同 → 直接進首頁。
3. 存進 localStorage，`history.replaceState` 把網址改回 `#/`（地址列、書籤、截圖不留資料）。
4. 顯示「設定完成 ✅」與一句：「之後直接打開這個網站就好，不用再點連結。」

### 2.2 「我需要幫忙」大按鈕（`#/help`）

- 首頁最上方、紅色、佔滿寬度、高度約 1/4 螢幕。
- 按下 → 全螢幕日文卡片（不顯示振假名與拼音，對方是日本人），內容依資料自動組合：

  ```
  すみません。
  {日本語|にほんご} が {話|はな}せません。{台湾|たいわん} から {来|き}ました。
  {道|みち} に {迷|まよ}いました。
  ─ 飯店卡 ─  この ホテル への {行|い}き{方|かた} を {教|おし}えて ください。
               〔飯店名〕〔地址〕〔電話〕
  ─ 家人卡 ─  {家族|かぞく} に {電話|でんわ} して いただけません か。
               〔關係・姓名〕〔電話（含從日本撥打的方式）〕
  ```
  每段下方小字中文給旅客自己看。整張可以上下捲動，也可以按「念出來」。
- 卡片下方的大按鈕：
  - 「念給對方聽」：依序念出各段。
  - 「打電話給家人」：`tel:` 連結（國際格式 `+886…`）。
  - 「給警察看」：顯示「最近的派出所（交番）在哪裡？」的日文＋交番的樣子說明（紅燈、門口寫 KOBAN／交番）。
- 緊急電話區（固定在卡片底部）：**110 警察**、**119 救護車・火災**、台北駐日經濟文化代表處急難救助電話、日本觀光局訪日旅客熱線。每個號碼都是 `tel:` 大按鈕，附一行中文說明。號碼**實作時上網查證**，原始碼註解標出處與查證日期（見 §6）。

### 2.3 情境句庫（`#/scene/<id>`）

情境（首頁大按鈕，順序即重要性）：

| id | 名稱 | 圖示（`src/ui/dom.ts` 的圖示名稱） | 句數目標 |
|---|---|---|---|
| `transport` | 交通 | `train` | 20（做最深） |
| `hotel` | 飯店 | `bed` | 12～16 |
| `restaurant` | 餐廳 | `bowl` | 12～16 |
| `konbini` | 便利商店 | `store` | 12～16 |
| `shopping` | 購物 | `bag` | 12～16 |
| `drugstore` | 藥妝店 | `pill` | 12～16 |
| `toilet` | 廁所・問路 | `restroom` | 12～16 |
| `emergency` | 緊急・醫療 | `firstaid` | 12～16（另有 §2.5 醫療卡） |

每一句都有：中文（大字，給自己看的）、日文（附振假名）、拼音、播放、慢速、「給對方看」全螢幕。
有 `answers` 的句子另外多一顆「給對方點選」（§2.4）。

**交通必備句**（用預先填好的站名，不用打字）：

| 句子 | 日文骨架 | 對方點選 |
|---|---|---|
| 我想去〇〇站 | `$dest まで {行|い}きたい です。` | — |
| 這班車有停〇〇嗎？ | `この {電車|でんしゃ} は $stop に {止|と}まります か。` | はい／いいえ |
| 去〇〇要在幾號月台？ | `$stop へ {行|い}く {電車|でんしゃ} は {何番線|なんばんせん} です か。` | 1～14 番線 |
| 我坐過站了 | `{乗|の}り{過|す}ごして しまいました。` | — |
| 我買錯票了 | `{切符|きっぷ} を {間違|まちが}えて {買|か}って しまいました。` | — |
| 卡片餘額不足（精算機在哪） | `{IC|アイシー}カード の {残高|ざんだか} が {足|た}りません。{精算機|せいさんき} は どこ です か。` | 方向 |
| 要在哪裡轉車？ | `$stop まで は どこ で {乗|の}り{換|か}えます か。` | — |
| 請幫我叫計程車／請載我到這裡 | `この {住所|じゅうしょ} まで お{願|ねが}い します。` | — |

`$dest` / `$stop` 是**站名插槽**：

- 有填目的地 → 句子上方出現一排大的「目的地按鈕」（今天的排前面），點選一個就把句子換成那個站名（有讀音就附振假名）。
- 沒有資料 → 使用 `fallback`（例：「ここ まで {行|い}きたい です。」＝我想去這裡）並提示「把寫好的地址或地圖給對方看」。
- `$dest` 是「名稱＋駅」（類型為車站時），`$stop` 只放名稱（「新宿 に 止まりますか」比較自然）。

### 2.4 雙向指指卡

**方向一：我問 → 對方點答案**（句子帶 `answers`）

全螢幕「給對方點選」模式：

```
┌──────────────────────────────┐
│ この電車は新宿に止まりますか。  │  ← 日文問題（大字）＋自動播放一次
│ 〔下の答えを指でタッチしてください〕│  ← 給對方的說明
├──────────────────────────────┤
│  [ はい ]      [ いいえ ]       │  ← 日文選項，大按鈕
│  [ わかりません ]               │
└──────────────────────────────┘
          ↓ 對方點「いいえ」
┌──────────────────────────────┐
│        不停（いいえ）           │  ← 給自己看的中文，超大字
│   [ 再問一次 ]   [ 關閉 ]       │
└──────────────────────────────┘
```

預設答案組（避免每句重寫）：`yesNo`、`platform`（1～14 番線＋わかりません）、`direction`（右／左／直走／後面／上樓／下樓／這裡）、`time`（現在／5 分後／10 分後／30 分後）。句子也可以自帶答案。每組都加「わかりません」。

**方向二：對方說 → 我看懂並回答**（每個情境的「店員可能會說」分頁）

情境頁頂端兩個分頁：「我要說」｜「對方說」（店員可能會說的話）。後者每一則：日文（附振假名）、▶ 播放、中文翻譯、下方 2～4 個中文回答按鈕（例：「要袋子嗎？」→〔不用〕〔要〕），點了就念出日文並放大顯示。

便利商店範例：袋子需要嗎、要加熱嗎、需要筷子／湯匙嗎、內用還是外帶、有集點卡嗎、要分開裝嗎、付款方式、需要收據嗎。

**萬用救援句**（每個情境頁最上方，可收合的「🛟 萬用句」；點選答案組最後都附「わかりません」）：

- 請用「是／不是」回答我：`はい か いいえ で {答|こた}えて ください。`
- 請寫在這裡：`ここ に {書|か}いて ください。`（MVP 不做手寫板，請對方寫在紙上）
- 請說慢一點：`ゆっくり {話|はな}して ください。`
- 請再說一次：`もう {一度|いちど} お{願|ねが}い します。`
- 我不會說日文：`{日本語|にほんご} が {話|はな}せません。`
- 請指給我看：`{指|ゆび}さして ください。`

### 2.5 醫療卡和過敏卡（`#/medical`）

- **醫療卡**（由設定資料自動產生，全日文＋小字中文）：姓名（護照英文）、出生年、國籍 台湾、慢性病、常用藥（成分）、藥物過敏、血型、家人電話、保險。
- **過敏卡**（餐廳用）：`わたし は 〇〇 の アレルギー が あります。〇〇 が {入|はい}って いる {料理|りょうり} は {食|た}べられません。` 列出項目；飲食限制另一句（素食：`{肉|にく} と {魚|さかな} は {食|た}べられません。`）。過敏卡同時出現在「餐廳」情境最上方。
- **症狀指指卡**：大圖示格狀（頭痛、發燒、腹瀉、噁心想吐、暈眩、胸痛、呼吸困難、肚子痛、咳嗽、跌倒受傷、出血、被咬或螫、喉嚨痛、皮膚癢疹）。點幾個 → 「給對方看」產生：`{次|つぎ} の {症状|しょうじょう} が あります：〔頭痛・発熱〕`。
- 固定句：「我有旅遊保險」、「請幫我叫救護車」、「請帶我去醫院」、「這是我常吃的藥」、「我有心臟病／糖尿病…」（由勾選項目產生）。
- 醫療相關的詞（藥名、症狀、過敏原的日文）實作時對照可靠來源（例：日本消費者廳的食物過敏標示、厚生勞動省／日本政府觀光局的外國旅客醫療指南），註解標出處。

### 2.6 紙本備份（`#/print`）

- 一鍵 `window.print()`，`@media print` 排成 A4，信用卡大小（85.6 × 54 mm）的卡片，含剪裁線，適合護貝放皮夾。
- 卡片：**飯店卡**（每間飯店一張，計程車用：「このホテルまでお願いします」＋名稱＋地址＋電話）、**求救卡**、**醫療卡**、**過敏卡**（有過敏或飲食限制才印）、**緊急電話卡**。
- 列印時一律淺色、黑字、不印網址列以外的介面元素。

## 3. 好讀好按的介面規則

| 規則 | 實作 |
|---|---|
| 預設超大字 | 字體兩檔：**大**（root 125%，預設）與**特大**（150%）。全部尺寸用 rem。中文最小 1.25rem（換算約 25px）。 |
| 按鈕大 | 主要按鈕高 ≥ 64px（4rem），次要 ≥ 56px；觸控間距 ≥ 12px。 |
| 選單一層 | 首頁＝情境大按鈕；進一層就是句子。全螢幕卡片是覆蓋層，按「關閉」或返回鍵回到原頁。 |
| 不打字不搜尋 | 使用中的頁面沒有任何 `<input>`（只有設定頁有）。站名用按鈕選。 |
| 圖示＋文字 | 情境用 emoji 大圖示（系統字型，離線可用）＋中文標籤；功能鍵用線條 SVG 圖示＋文字，不只放圖示。 |
| 對比 | 淺色與深色兩套 token，所有文字／底色組合 ≥ 4.5:1（WCAG AA），大字也照 4.5:1 算。寫一個測試檢查 token 對比。 |
| 深色模式 | 跟隨系統／淺色／深色，沿用 ippo 的 `data-theme` 做法，`index.html` 內聯腳本避免閃白。 |
| 直向優先 | 一般頁面為單欄直向；全螢幕卡片字級用 `min(vw, vh)` 計算，橫拿時放大、不被裁切。 |
| 動畫 | 遵守 `prefers-reduced-motion`。 |
| 返回 | 每頁左上「← 回首頁」大按鈕（不只依賴系統返回鍵）。 |

## 4. 頁面與路由

路由一律在 `#` 之後（沿用 ippo 的 `PAGES` 表），網站放在任何子路徑都能運作；`vite.config.ts` 設 `base: "./"`。

| 路由 | 頁面 | 誰用 |
|---|---|---|
| `#/` | 首頁 | 旅客 |
| `#/help` | 我需要幫忙（全螢幕求救卡） | 旅客 |
| `#/scene/<sceneId>` | 情境：我要說 | 旅客 |
| `#/scene/<sceneId>/heard` | 情境：店員可能會說 | 旅客 |
| `#/medical` | 醫療卡、過敏卡、症狀指指卡 | 旅客 |
| `#/hotel` | 回飯店卡（給計程車司機看） | 旅客 |
| `#/settings` | 字體大小、深色模式、語音、語速、聽不到聲音怎麼辦 | 旅客 |
| `#/setup` | 設定表單 | 設定者 |
| `#/share` | 分享連結＋QR code＋隱私提醒 | 設定者 |
| `#/print` | 列印護貝小卡 | 設定者 |
| `#/s/<version>.<payload>` | 匯入（處理完立刻換成 `#/`） | 旅客 |

全螢幕卡片（給對方看、給對方點選）是覆蓋層而非路由，沿用 ippo `showToClerk` 的做法：焦點鎖在覆蓋層、Esc／返回鍵（`hashchange`）關閉、`aria-modal`。差別是 daijoubu 會在開啟覆蓋層時 `pushState` 一筆，讓 Android 返回鍵關掉覆蓋層而不是離開頁面。

## 5. 資料結構

### 5.1 日文標記

沿用 ippo 的語法（`src/lib/jp.ts`、`src/lib/romaji.ts` 直接複製後獨立維護）：

- 詞與詞之間一個半形空格；漢字寫成 `{漢字|かな}`；助詞「は」「を」獨立成詞。
- 新增**插槽**：以 `$` 開頭的整個詞，例如 `$dest`、`$stop`、`$hotel`。展開時換成使用者資料的標記；展開前的句子只有在提供 `fallback` 時才能直接顯示。
- 使用者填的日文（站名、飯店名、地址）不是標記語法：讀音有填就變成 `{新宿|しんじゅく}`，沒填就當成「純文字片段」顯示（不加振假名、不產生拼音，語音直接念原文）。地址只顯示不轉拼音。

## 6. 分享連結編碼

```
https://<user>.github.io/travel-buddy/japan/#/s/1.<payload>
                                    │ └─ base64url( deflate-raw( UTF-8( JSON( wire ) ) ) )
                                    └─── 格式版本
```

- **wire 格式**：Profile 轉成短鍵名的 JSON（例：`{"n":"媽媽","h":[{"n":"…","a":"…"}],…}`），空欄位整個省略。對照表寫在 `src/share/codec.ts`，有往返測試。
- **壓縮**：`fflate`（約 8 KB、MIT、同步、Node 測試裡也能跑）。不用 `CompressionStream`，因為 iOS 16.4 以前沒有，而旅客的手機可能很舊。
- **base64url**：`+/` → `-_`，去掉 `=`，在 LINE、簡訊裡不會被截斷或轉義。
- **大小預算**：一般資料（2 間飯店、6 個目的地、2 位家人、3 種藥）約 1,000 字元。超過 1,500 字元時在分享頁提示「QR code 會比較密，建議用連結傳」。QR code 用 `qrcode-generator`（MIT，無相依）產生 SVG，錯誤更正等級 L。
- **版本**：`1.` 之後只增不改；未來改格式就用 `2.`，舊連結照樣能解。
- **安全**：解碼後一律走 `parseProfile`，不信任任何欄位；`#` 之後的內容不會傳到伺服器，但會留在**聊天紀錄**和**瀏覽器歷史**——這就是分享頁要提醒的原因。匯入後立刻 `replaceState` 清掉網址。

### 已知風險

**Safari 對 7 天沒開的網站可能清掉 localStorage（ITP）。** 太早設定的話，到日本時資料可能不見了。
對策：分享頁提醒「出發前一兩天再傳，出發當天打開一次」；資料空白時首頁顯示「還沒有你的資料：請點開分享連結，或到設定資料填寫」；紙本小卡是最後防線。

## 7. 語音

直接複製 ippo `src/lib/speech.ts` 後獨立維護：挑音質好的語音（Premium／Enhanced／Google…）、避開 Eloquence 怪聲、`voiceStatus()` 偵測沒有日文語音、`speak()` 的逾時保護。

- 預設語速 0.9；「慢速」0.6。

### `npm test` 檢查的內容規則

- 每段日文標記都能解析；每個漢字、英數字都有 `{|かな}` 讀音；讀音只能是假名；全形空白禁止。
- 所有 id 全域唯一、kebab-case。
- 每句都有非空的中文；每則「店員可能會說」至少 2 個回答。
- 每個情境至少 **12** 句「我要說」、至少 **4** 則「店員可能會說」；交通至少 18 句。
- 有插槽的句子一定要有 `fallback`；插槽名稱必須是已知的。
- 交通情境必須包含指定的 6 個必備句 id。
- 緊急電話每一筆都有 `source` 和 `verified`（日期）欄位。
- 設計 token 的文字／底色組合對比 ≥ 4.5:1（淺、深兩套）。
- 分享編碼：往返相等；壞掉、截斷、超長的 payload 不會丟例外；典型資料 < 1,500 字元。

## 14. 電梯（2026-10-11）

評估後決定**不做站內電梯地圖**，原因有四：
- 資料分散在各鐵路公司，大多只有日文網頁，沒有可以直接使用的開放資料。
- 電梯會增設、也會停用維修，內建的資料一定會過期。
- 站內圖對不熟的人很難讀。
- Google 地圖已經有輪椅路線可以用。

改做兩件事：
1. **電梯問句**：交通新增「電梯・不走樓梯」分組，有這幾句：哪個出口有電梯（`exit` 答案組：東／西／南／北／中央口、寫在紙上、不知道）、到月台的電梯在哪、電梯在剪票口內還是外、請站務員帶我去。「對方說」新增「電梯在剪票口外」「電梯現在不能用」。
2. **電梯筆記**：每個目的地新增 `Place.note`（分享連結的 wire key 是 `e`）。家人出發前查好填入，設定頁有查詢方法。交通頁選到那一站時，筆記會出現在選站列下方；也可以放大給站務員看，畫面上方會先念「エレベーターを使いたいです」，下面顯示筆記原文。
